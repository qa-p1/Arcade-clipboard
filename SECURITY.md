# Security policy

## Reporting

Report a vulnerability privately through GitHub's "Report a vulnerability" (Security tab of this repository), not in
a public issue. Expect an answer within a week. Fixes ship as a patch release through the normal rc → promote path. A
release found to be unsafe after it shipped gets the catalog's `bad` flag: Arcade Tools stops offering it and tells
installed copies to roll back.

## What Arcade Clipboard guards, and how

Clipboard keeps a history of what you copy: text, URLs, rich text (HTML), PNG and JPEG images, and files (up to
16 MiB per clip). It stores the history in a local SQLite database, `history.sqlite`, in its own data folder, and
encrypts each clip and its preview with a key kept in the system credential store (Secret Service on Linux, Keychain,
Credential Manager, Android Keystore). Unlike Find, Clipboard **has network code**: once a device has set up or joined
a mesh, the core listens on a TCP port on all IPv4 interfaces, announces itself on the local network over mDNS, and
syncs clips with your other devices over Noise-encrypted connections (`core/rust/src/core/peers.rs`,
`core/rust/src/discovery.rs`). An optional relay (`services/relay`, a separate server you run yourself) can carry the
same encrypted stream over `wss://`; it is off until a relay address is set. The core's dependency tree includes
`tokio-tungstenite` with rustls (`cargo tree -p arcade_core`); it contains no HTTP client (no `reqwest`, `hyper`,
`ureq` or `openssl`). The Dart code imports no HTTP or WebSocket package and loads no web view. Clipboard does not
simulate keystrokes on Wayland except through Hyprland, and does not read the screen. A corrupt history is never
replaced silently (see Files stored).

| Files stored | `history.sqlite` (WAL mode, `secure_delete` on) holds each clip and its preview encrypted with XChaCha20-Poly1305, with the record header as associated data; the key is the database key inside the secure identity (next row). Record headers (ids, device names, times, kind), the device list, the mesh id and the relay address are not encrypted. Content matching uses a BLAKE3 tag keyed per profile. Limits: at most 10,000 items and a 256 MB storage budget by default (16 MB to 64 GB; the oldest unpinned clips go first, pinned clips are never pruned); retention defaults to Forever (`0`) and can be set from 1 hour to 10 years. A database from a newer version is refused, and a damaged or unauthenticated record fails to open with an error; Clipboard never deletes or recreates the file. `settings.json` is written to a temporary file and renamed; a damaged `settings.json` starts over empty. On Linux and macOS the app sets the data folder to mode 0700 at every start (`_makePrivate` in `apps/flutter_app/lib/services/app_controller.dart`), so `history.sqlite`, `profile.lock`, `settings.json` and `logs/` inside it are the user's alone; the files themselves are created with the process umask. On Windows and mobile the app folder is per-user. Copying or pasting a **file** clip writes its decrypted bytes to `<data>/clipboard-files/<clip id>/<name>` so the system clipboard can offer them as files: only the clip copied last is kept there (each new export removes the earlier ones), its folder is removed when the clip is deleted or the whole history is cleared, and the folder is mode 0700. Images are cached only in memory (24 MiB). | `core/rust/src/store.rs` (`local_history_is_encrypted_and_searchable`, `authenticated_metadata_and_nonce_are_checked_before_returning_history`, `binary_history_uses_a_small_encrypted_authenticated_preview`, `a_new_history_keeps_clips_forever_within_256_mb`, `the_budget_removes_the_oldest_unpinned_clips_and_never_pinned_ones`, `retention_is_this_devices_own`, `wire_item_metadata_is_bounded`), `core/rust/src/profile_lock.rs` (`concurrent_open_is_rejected_and_drop_releases_lock`), `apps/flutter_app/test/app_settings_test.dart` (`a new profile starts empty and a damaged file does not stop the app`), `apps/flutter_app/test/image_cache_limit_test.dart` (`the decoded image cache is capped at 24 MiB, below Flutter default`). File modes and the `clipboard-files` folder are not covered by a test. |
| Secure identity | One secret per profile in the system credential store: service `arcade-clipboard`, account `identity-v1-<BLAKE3 of the profile folder path>` (`core/rust/src/secret.rs`). It is 149 bytes: the device's Noise static key pair, the **database key**, the device id and, on the mesh owner, the mesh signing key. No plaintext or file fallback exists: with no usable credential store the profile does not open, a missing secret for an existing `history.sqlite` is an error ("refusing to replace it"), and a damaged one fails a key-consistency check. After the 0.2 folder move, a credential stored under an old Link folder path is adopted only after a read-only check authenticates the existing database (and signed membership, if present); several conflicting matches are refused, and custom profile folders never borrow the default profile's. On Android the secret is a file in `noBackupFilesDir` encrypted with an AES-GCM Keystore key (`CoreIdentityStore.kt`). | `core/rust/src/secret.rs` (`missing_secret_for_existing_database_fails_closed`, `missing_secret_without_database_allows_first_run`, `system_secret_profiles_are_canonical_and_isolated`, `migrated_identity_recovery_preserves_history_mesh_and_legacy_credential`, `recovery_rejects_wrong_missing_conflicting_and_unbound_credentials_without_writes`, `custom_profiles_cannot_adopt_default_legacy_identities`, `migrated_profile_recovers_from_real_secret_service`); CI runs the last one against a private gnome-keyring through `scripts/verify-identity-migration.py`. The Android Keystore code is not covered by a test. |
| Relay, sync and network | Clipboard connects to nothing until a device has a mesh. **Direct:** the owner listens on TCP `0.0.0.0` (persisted port; at most 32 handshakes at once, 12 s handshake timeout, 64 KiB frames, 45 s read timeout) and announces `_arcade-clip._tcp.local.` over mDNS with the mesh id, device id and public key. Every connection runs a Noise handshake (`Noise_XX_25519_ChaChaPoly_BLAKE2s`, or `Noise_XXpsk3_…` with a one-time invite token for pairing) and the peer's static key must match an owner-signed, unrevoked membership certificate. An invite lasts 120 s and is single-use; pairing needs a six-digit verification code and approval. Clips are signed by their originating device. Clips from other devices are never written to your clipboard automatically. **Relay:** off by default (the address is empty, or taken from `ARCADE_RELAY_URL`). The address must be `wss://`, or `ws://` for localhost only, with no credentials, query, fragment or path, at most 2048 bytes; a joining device adopts the owner's relay address from the invite. The relay sees only Noise ciphertext, the devices' IP addresses, timing and volume; the route id and access ticket are derived from the two devices' shared secret and sent as a query string (`?token=…`), which a proxy in front must not log. The relay service itself speaks plain HTTP/WebSocket on `127.0.0.1:8787` by default, expects a TLS-terminating proxy for public use (`deploy/relay/Caddyfile` disables access logging), keeps state in memory only, forwards binary frames of at most 64 KiB, and caps 512 connections, 16 per IP, and 120 upgrades per IP per minute. It logs only its listen address. Clipboard also opens a UDP socket and `connect`s it to `1.1.1.1:80` to learn its LAN address (no packet is sent). | `core/rust/src/core/peers.rs` (`relay_routes_are_pairwise_secret_and_symmetric`), `core/rust/src/relay_transport.rs` (`relay_addresses_must_be_secure_and_carry_nothing_but_the_server`), `core/rust/src/transport.rs` (`real_noise_pairing_encrypts_and_authenticates_both_directions`, `altered_ciphertext_is_rejected`, `wrong_pairing_ticket_cannot_complete_handshake`, `frame_rejects_zero_oversize_and_truncated_input`), `core/rust/src/crypto.rs` (`membership_signature_rejects_tampering`, `pairing_sas_is_stable_for_both_sides`, `revocation_requires_owner_signature_and_binds_mesh_device_and_epoch`, `origin_signatures_reject_plaintext_metadata_and_payload_tampering`), `core/rust/src/integration_tests.rs` (`pairing_exact_text_deduplication_and_consumed_invitation`, `rejection_establishes_no_trust_and_settings_survive_restart`, `revocation_closes_live_session_and_rejects_reconnect`, `encrypted_relay_pairing_offline_queue_and_reconnection`, `lan_loss_switches_to_relay_and_sync_continues_without_duplicates`, `private_mode_holds_back_the_backlog_until_it_ends`), `services/relay/tests/websocket_transport.rs` (`invite_tunnel_preserves_binary_messages_and_rejects_replay`, `invalid_ticket_cannot_join_or_consume_the_legitimate_route`, `paired_routes_reconnect_only_with_matching_token_and_distinct_slots`, `oversized_message_closes_tunnel_without_forwarding`), `services/relay/src/lib.rs` (`only_32_byte_unpadded_base64url_tokens_are_accepted`, `route_ids_are_bounded_and_url_safe`, `connection_caps_are_released_after_disconnect`). TLS itself (rustls) and the mDNS announcement are not covered by a test. |
| Link IPC | Link is on by default (`link_enabled` defaults to true). Clipboard offers three actions to other Arcade apps (`core/rust/src/link.rs`): `clipboard.add` ("Send to my devices": one text, image or file input, at most 16 MiB and 32 files, effect `sends-to-device`; it reads the named files from disk, and Private mode refuses it), `clipboard.pick` (opens Clipboard's picker, and only the clip you choose goes back to the caller; the clip is written to a Link handoff folder and kept there with `h.keep()`), and `clipboard.devices` (device name, platform and online state, with no keys or ids). Clipboard also sends a clip you selected to Box, Lens, Look, Shelf or Tools on your request (`core/rust/src/link_consumer.rs`); it refuses inputs hinted `secret`, refuses results with secret findings, and refuses in Private mode. "Connected apps" off sets `link_enabled` false in Clipboard's manifest, cancels running jobs, drops staged images and hides every peer action (`configure`); what Link's server does with that flag is not verified here. Socket permissions and peer checks are Link's and are not described here. | `core/rust/src/link.rs` (`exposes_the_catalog_actions`, `text_becomes_a_clip_with_long_text_as_a_representation`, `files_become_image_or_file_clips_within_the_limits`, `capture_errors_map_to_link_codes`, `picked_clips_become_link_content`, `devices_list_other_devices_without_ids`), `core/rust/src/link_consumer.rs` (`offers_hide_missing_disabled_unavailable_and_wrong_kind`, `shelf_offers_every_clip_kind_and_hides_when_off`, `tools_install_is_not_a_clip_action`), `apps/flutter_app/test/link_service_test.dart` (`launch mode stays separate from preferences and connection toggles`). That a file path outside Link's handoff folder is accepted by `clipboard.add`, and that the secret check works end to end, are not covered by a test. |
| Instance channel | On Linux one resident instance per user owns the D-Bus session-bus name `dev.arcade.Clipboard` (GApplication); a second launch activates one of six actions with no arguments or payload: `show`, `overlay`, `settings`, `hide`, `toggle`, `quit` (`apps/flutter_app/linux/runner/my_application.cc`). There is no token: the session bus is the boundary. With `ARCADE_DATA_DIR` set (development profiles) the instance is not unique. On Windows and macOS a second launch calls the running instance over Arcade Link with `app.activate`, `app.settings`, `app.menu.invoke` (`cli.overlay`, `cli.hide`, `cli.toggle`), `app.quit` or `app.restart`. Separately, `profile.lock` (an exclusive file lock) keeps two processes from opening one profile. `--restart` starts a successor with `ARCADE_CLIPBOARD_RESTART_AFTER` set to the old process id and waits up to 5 s for it to exit. | `apps/flutter_app/test/desktop_commands_test.dart` (`a second launch asks the running copy for the matching surface`, `status, help and restart answer without opening the app`), `apps/flutter_app/test/restart_test.dart` (`CB-4: restart re-executes the AppImage file, not the mounted binary`), `core/rust/src/profile_lock.rs` (`concurrent_open_is_rejected_and_drop_releases_lock`). The D-Bus actions are not covered by a test that CI runs (`tests/linux_bundle_acceptance.py` exercises `--quit` but no workflow invokes it). |
| Child processes | No shell sees clipboard content. Started with `runInShell: false` and fixed arguments: `wl-paste --list-types`, `wl-paste --no-newline --type <target>` and `wl-paste --version`; `arcade_clipboard_wl_capture --watcher-events <wl-paste> <helper>`, `--signal-group <term\|kill> <pid>`; `xdotool getactivewindow`, `getwindowclassname <id>`, `windowactivate --sync <id>`, `getwindowfocus`, `key --clearmodifiers ctrl+v` (or `ctrl+shift+v` for a terminal); `hyprctl` (`-j clients`, `-j binds`, `-j activewindow`, `-j status`, `eval …`, `dispatch …`, `keyword bind/unbind …`); the app's own executable with `--background` on restart. `wl-copy` runs as `/bin/sh -c 'exec "$0" "$@" >/dev/null 2>&1' <wl-copy> [--type <mime>]`: the script is fixed, the clip travels on stdin. The Hyprland shortcut is a bind whose command is `sh -c ': <marker>; test "$(sed … /proc/<pid>/stat …)" = "<ticks>" && kill -USR1 <pid>'`, built only from the process id and its start time; window addresses are checked against `^0x[0-9a-fA-F]+$`. Programs are found by name on `PATH`. `xdg-open` (Windows `explorer`, macOS `open`) opens the logs folder, the user guide and the releases page; the core's `open_releases` runs `xdg-open`, `open` or `rundll32.exe url.dll,FileProtocolHandler` on Link's release URL for a known Arcade app. A peer app's Link manifest executable is started without a shell (`Command::new(&manifest.executable)`, arguments from its manifest) when an action runs one-shot. Windows login shortcuts use `powershell.exe -NoProfile -NonInteractive -Command`; macOS uses `/usr/bin/plutil`, `/usr/bin/open`; the restart wait uses `kill -0` or `tasklist`. | `apps/flutter_app/test/wayland_clipboard_test.dart` (`an ordinary selection is read, and is not marked sensitive`), `core/rust/src/windows_login.rs` (`powershell_shortcut_paths_are_literal_and_start_in_background`), `apps/flutter_app/test/restart_test.dart` (`restart from the unpacked copy starts the successor as a fresh start`). The `xdotool`, `hyprctl`, `xdg-open` and peer launches are not covered by a test that runs in CI (`tests/native_paste_target.c` and `integration_test/native_app_test.dart` need a live Hyprland session and are run by hand with `scripts/test-native-linux.sh`). |
| Paste into other apps | Clipboard never types text. To paste it puts the clip on the clipboard, returns focus to the window that was active when the picker opened, and sends the paste chord once, only if that window is still the one remembered. Linux X11: `xdotool` (above), re-checking `getwindowfocus` before the keystroke. Hyprland: `focuswindow` then `sendshortcut <mods>,V,address:<addr>`, after checking the window's address, PID and process start time. Other Wayland desktops: no key injection, copy only. Windows: `SetForegroundWindow` then `SendInput` of Ctrl+V, after checking window handle, owner PID and process creation time at the last moment. macOS: `CGEvent` Command+V posted to the HID tap, needs the Accessibility permission, after checking the same process. On any failed check the clip stays copied and nothing is sent. | not covered by a test that runs in CI (`tests/native_paste_target.c` is a GTK target for the by-hand Hyprland run in `scripts/test-native-linux.sh`). |
| Windows and UI | Flutter desktop and mobile, native widgets only: no web view, no remote images (no `Image.network`), no HTTP client in the Dart code. Clips are shown as text and decoded thumbnails. The only URLs opened are the user guide, the releases page and Link's release pages, in your browser, on a click. | not covered by a test |
| Logs and diagnostics | Clipboard **content does not reach the logs**: `Diagnostics.log` lines (`apps/flutter_app/lib/services/diagnostics.dart`) are event text such as `read clipboard: 3 formats, sensitive=false` and `stored text clip`; each line is cut at 2048 characters. They go to an in-memory ring of 200 lines and to `<data>/logs/diagnostics.log`, rotated to `diagnostics.log.1` at 1 MiB, created with the default umask; `ARCADE_DEBUG=1` also echoes them to stderr. The core prints to stderr only "Private mode on/off (cause: …)" and a tray warning. Two lines include an exception text (`core rejected clip: $exception`, `restart failed: $error`); the core's error strings checked are fixed messages, but not every one has been audited. "Copy diagnostics" puts on the clipboard: Link's header (versions, channel, peers), OS name and version, whether a mesh exists, the number of devices and pairing requests, connection state, `Relay: configured` or `none` (never the address), Private mode, how many clips are loaded, retention and item limit, and the last 60 log lines; no clip content, keys or relay ticket. Nothing is uploaded. The relay logs only its listen address. | not covered by a test (the fake core in `apps/flutter_app/test/test_fakes/fake_core_api.dart` returns a diagnostics header, but no test reads the copied text) |
| Crash reports | Clipboard writes none and sends none. A crash leaves the local stderr and `diagnostics.log` lines above. | not covered by a test |
| Updates | Clipboard is installed and updated by Arcade Tools, which trusts a release through its signed `manifest.json`: `.github/workflows/promote.yml` republishes a verified release candidate with a manifest signed by `ARCADE_UPDATE_SIGNING_KEY` and publishes nothing without it. Clipboard itself downloads nothing: the Linux launcher (`platform/linux/launcher`) installs the AppImage you already downloaded and its `--channel` only records which channel the receipt names; "Releases" in Settings opens the GitHub releases page in your browser. | Arcade Tools' tests; Clipboard's own update path is not covered by a test. |
| Android and iOS | The mobile apps hold the same encrypted database and identity (Keystore on Android, Keychain on iOS). They ask for `INTERNET` and `CAMERA` (to scan a pairing QR code); iOS also declares local-network use. Content enters through the Share target, the keyboard (Android `MeshClipboardIme`, iOS keyboard extension) or in the app; there is no background clipboard reader. Android's shared store is encrypted with a Keystore AES-GCM key under `noBackupFilesDir`, with an inbox of at most 100 items and 64 MiB, kept for 7 days, and a keyboard cache of at most 30 items and 2 MiB, 7 days; the iOS shared files live in the App Group and are written with `completeFileProtection`. The iOS keyboard sets `RequestsOpenAccess`. Mobile apps sync only over the mesh transport described above; the Android share target is exported and accepts `text/plain`, `text/uri-list`, `image/*` and `application/*`. Mobile does not use Arcade Link. | not covered by a test (the Kotlin and Swift code has no test in this repository; `apps/flutter_app/ios/RunnerTests` and `macos/RunnerTests` hold only the Xcode template) |

## Dependencies

`cargo deny check --workspace --all-features` (advisories, licences, bans, sources) runs in CI as the `deny` job
(`.github/workflows/ci.yml`) against `deny.toml`. `deny.toml` ignores **no advisories** (`ignore = []`, with the note
that every advisory in the lock file was fixed by updating), denies yanked crates, denies unknown registries and git
sources apart from Arcade Link (`https://github.com/qa-p1/Arcade-Link`, pinned to tag `v1.0.13`), denies wildcard
version requirements, and allows only the licences it lists. The `rust` job also runs `cargo fmt --check`,
`cargo clippy -D warnings` and `cargo test --workspace --locked` (`scripts/check rust`, `scripts/dev`), plus the Secret
Service identity test; the Flutter jobs run `flutter pub get --enforce-lockfile`, `dart format`, `flutter analyze` and
`flutter test`.

`.github/dependabot.yml` opens weekly, grouped pull requests for minor and patch updates of cargo (`/`), pub
(`/apps/flutter_app`) and github-actions (`/`), with majors separate and automatic rebase off.

Third-party licences are generated by `scripts/notices.py` into `THIRD_PARTY_NOTICES.md`. It reads the normal
dependency graph of the shipped packages `arcade_core` and `arcade-clipboard-launcher` for every target
(`cargo metadata --locked`), the C code built in (SQLite, libdbus), the Dart packages the app depends on without dev
dependencies (`dart pub deps`), the Flutter framework, vendored `hotkey_manager_linux`, the Inter and Material Icons
fonts, the files copied from Arcade Link (`scripts/VENDORED`) and the AppImage runtime components. It does not cover
`services/relay` or `tests/driver`, nor the Windows, macOS, iOS and Android platform libraries. `scripts/native-notices.py`
extracts a built AppImage, maps every bundled ELF file to its Ubuntu package with `dpkg -S`, records each package's
`copyright` file under `packaging/linux/native/`, fails on a bundled library that no package owns, and with `--check`
also requires Flutter's `NOTICES.Z` and a copy of `THIRD_PARTY_NOTICES.md` identical to the repository's. The CI `linux`
job runs `scripts/notices.py --check` and `scripts/native-notices.py --check` on the AppImage it builds
(Ubuntu 22.04), and uploads the regenerated `packaging/linux/native/` record when it is out of date.
